# User Stories: Система учёта инвентаря компьютерных классов

Формат: «Как [роль], я хочу [действие], чтобы [польза]». Отметка выполнения ставится по итогам приёмки в спринте 5.

## US-1. Просмотр списка оборудования

Как лаборант, я хочу видеть все инвентарные записи в одном списке, чтобы быстро оценить наличие техники в кабинетах.

Критерии приёмки:
- при выборе пункта 1 выводится таблица со всеми записями;
- таблица содержит номер, тип, наименование, кабинет и состояние;
- если список пуст, выводится сообщение «Список пуст»;
- программа не завершается аварийно.

Статус: выполнено.

## US-2. Добавление новой записи

Как лаборант, я хочу добавлять новое оборудование с автоматическим номером, чтобы не придумывать инвентарный номер вручную.

Критерии приёмки:
- при выборе пункта 2 программа запрашивает тип, наименование, кабинет и состояние;
- номер генерируется автоматически в формате INV0001;
- пустые поля не принимаются, выводится сообщение об ошибке;
- после добавления запись видна в общем списке и сохранена в файле.

Статус: выполнено.

## US-3. Поиск по инвентарному номеру

Как лаборант, я хочу находить компьютер по инвентарному номеру, чтобы быстро узнать, в каком кабинете он находится.

Критерии приёмки:
- поиск по существующему номеру показывает карточку записи;
- по неизвестному номеру выводится сообщение «Не найдено»;
- ввод пустого номера не приводит к аварии;
- программа остаётся в меню после поиска.

Статус: выполнено.

## US-4. Поиск по кабинету

Как заведующий кабинетом, я хочу находить всё оборудование в указанном кабинете, чтобы проводить инвентаризацию.

Критерии приёмки:
- поиск по кабинету выводит все записи с этим кабинетом;
- если совпадений нет, выводится сообщение «Не найдено»;
- поиск не изменяет данные.

Статус: выполнено.

## US-5. Изменение состояния или кабинета

Как лаборант, я хочу изменять состояние или кабинет существующей записи, чтобы отражать ремонт или перемещение техники.

Критерии приёмки:
- при выборе пункта 4 программа запрашивает инвентарный номер;
- если запись найдена, предлагается изменить состояние или кабинет;
- после изменения данные сохраняются в файл;
- если запись не найдена, выводится сообщение об ошибке;
- неверный ввод не завершает программу аварийно.

Статус: выполнено.

## US-6. Удаление записи с подтверждением

Как лаборант, я хочу удалять списанное оборудование, но только после подтверждения, чтобы избежать случайной потери данных.

Критерии приёмки:
- при выборе пункта 5 программа запрашивает инвентарный номер;
- перед удалением запрашивается подтверждение;
- при отказе запись остаётся без изменений;
- при подтверждении запись удаляется и файл JSON обновляется;
- при несуществующем номере выводится сообщение об ошибке.

Статус: выполнено.

## US-7. Сохранение данных между запусками

Как лаборант, я хочу, чтобы все изменения сохранялись в файле, чтобы данные не пропадали после закрытия программы.

Критерии приёмки:
- после добавления, изменения или удаления данные сохраняются в data/inventory.json;
- при следующем запуске записи загружаются из файла;
- при отсутствии файла программа создаёт пустой список и продолжает работу;
- при повреждённом JSON программа не теряет данные незаметно и выводит предупреждение.

Статус: выполнено.
